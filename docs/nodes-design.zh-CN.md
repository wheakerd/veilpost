# 节点功能设计（草案）

[English](nodes-design.md) | 简体中文

状态：第 1 阶段（节点注册与控制通道）已实现，其余阶段待实施。接口契约见 `app/frontend/docs/nodes-api.md`。

## 目标与范围

- 抗主动扫描：未认证的探测只能看到真实网站或得不到任何回应。
- 抗 DPI 与流量伪装：握手外观和包长特征接近常见合法流量。
- 防止单协议长连接：同一节点同时提供 TCP、HTTP 和 UDP 三类入口；底层连接定期更换，客户端可在入口之间切换。
- 规模：自用，少量节点（10 个以内），一两个管理员。不做计费、配额和多租户。
- 开源：代码和文档不含任何私人域名、地址、密钥或部署路径；所有站点、端口和参数都由使用者配置或在节点上随机生成。

非目标：保证不被识别。轮换和伪装提高识别成本，但单个 IP 长期的大流量本身就是特征，文档和界面不承诺“不可检测”。

## 总体结构

```text
浏览器 ──/api/auth, /api/nodes──▶ 控制台 (app/backend)
                                      ▲
                                      │ HTTPS，节点主动发起，签名请求
                                      │
节点 ── veilpost-agent (app/agent) ──管理──▶ Xray / Hysteria2 / AmneziaWG 容器
```

- `app/agent/`：新的 Go 程序 `veilpost-agent`，CGO-free，单二进制，随发布包分发。
- 节点不开放管理端口。代理程序通过长轮询向控制台拉取期望配置并上报状态：服务端最长保持 25 秒，返回后立即重连。
- 控制台新增 `/api/agent/*`（节点调用，签名认证）和 `/api/nodes/*`（浏览器调用，沿用会话认证与 CSRF 规则）。
- 节点上的服务以 Docker 容器运行，与 `docker/soft-router/` 参考配置一致；代理程序生成 Compose 文件并调用 `docker compose`，不直接持有 Docker 守护进程之外的权限。

## 控制通道

### 注册

1. 管理员在控制台创建节点，得到一次性注册令牌（随机 256 位，15 分钟有效，库中只存哈希）。
2. 在节点上执行 `veilpost-agent enroll --server https://console.example --token-stdin`，令牌走标准输入。
3. 代理程序在本地生成 Ed25519 密钥对，提交公钥，并附上用新私钥对令牌哈希和公钥的签名作为持有证明；公钥在控制台唯一。控制台核销令牌并绑定节点。私钥只保存在节点的 `0600` 文件中。

### 请求认证

- 每个请求带 Ed25519 签名，签名内容为 `vpn-agent-v1`、HTTP 方法、接口路径、节点 ID、时间戳、随机数和请求体 SHA-256；时间偏差超过 60 秒拒绝，随机数在有效期内去重，防重放。
- 签名而非 mTLS：控制台可以放在 Nginx 或 CDN 后面，不需要自建 CA。
- 控制台可吊销节点，吊销后签名立即失效；重新接入需要新的注册令牌。
- `/api/agent/*` 有独立的按节点限流，不与登录限流共用额度。

### 配置下发

- 控制台为每个节点维护递增的配置版本号；代理程序带上当前版本长轮询，有新版本时取回完整期望状态。
- 代理程序在本地渲染配置，先用各服务自带的校验（如 `xray run -test`）检查，通过后再替换并重启对应容器；失败时保留旧配置并上报错误。

## 密钥归属

| 数据                                        | 生成位置 | 控制台保存                              |
| ------------------------------------------- | -------- | --------------------------------------- |
| REALITY 私钥                                | 节点     | 只存公钥                                |
| AmneziaWG 服务端私钥                        | 节点     | 只存公钥                                |
| AmneziaWG 客户端私钥                        | 控制台   | `master.key` 加密，导出客户端配置时解密 |
| VLESS UUID、REALITY shortId、Hysteria2 密码 | 控制台   | `master.key` 加密；同时下发到节点       |
| 节点签名私钥                                | 节点     | 只存公钥                                |

客户端凭据必须能再次导出，所以只能加密保存，不能只存哈希。

## 入口协议

每个节点默认启用以下四种入口，端口可配置；同一协议的参数按节点随机生成，避免所有部署共用同一组特征值。

### 1. VLESS + REALITY + Vision（TCP）

- 默认 TCP 443；`flow: xtls-rprx-vision`；客户端 uTLS 指纹 `chrome`。
- 借用站点（`target` 与 `serverNames`）由管理员填写，不提供默认值。代理程序从节点侧检查候选站点：TLS 1.3、HTTP/2、X25519、无跳转，不满足则拒绝启用。
- 每个客户端独立 shortId，可单独吊销。

### 2. VLESS + XHTTP + REALITY（TCP）

- 独立端口（默认随机高端口，可改为 8443 等）；同样使用 REALITY，借用站点可与入口 1 不同。
- 防长连接的核心：客户端 XMUX 参数在范围内随机，限制单个底层连接的复用次数和存活时间，到期自动建立新连接，例如：
    - `cMaxReuseTimes`、`hMaxRequestTimes`、`hMaxReusableSecs` 使用区间值；
    - `maxConcurrency` 与 `maxConnections` 二选一。
- `mode` 显式设置，不用 `auto`（已有 `auto` 在 REALITY 下连接失败的问题报告）。
- 后续阶段可选：用 `downloadSettings` 让上下行走不同地址或入口。

### 3. Hysteria2（UDP）

- 默认 UDP 443，与入口 1 共用端口号但不冲突。
- 服务端使用官方镜像 `tobyxdd/hysteria`（由 `apernet/hysteria` 仓库发布）。Xray 自带的 Hysteria2 入站是新功能，已有握手失败的报告，暂不采用，后续复评。
- 两种伪装模式按节点选择：
    - 伪装（默认）：看起来是 HTTP/3，未认证请求由 masquerade 站点应答，抗主动探测；
    - Salamander 混淆：看起来是随机 UDP，不暴露 QUIC 特征，但无法应答探测。

### 4. AmneziaWG（UDP）

- 服务端镜像位于 `docker/node/amneziawg/`：从上游固定提交构建 `amneziawg-go v3.1.20261116` 与 `amneziawg-tools v3.1.20260812`，源码归档校验 SHA-256，基础镜像按摘要固定。目前容器在本地生成服务端密钥和首个客户端；接入 `veilpost-agent` 时需要增加由外部提供配置与 peers 的启动方式，以符合“密钥归属”表，并把共享混淆参数（含 HeaderProtectionKey，按 `master.key` 加密保存）上报控制台。
- 使用 2.0 参数：Jc/Jmin/Jmax、S1–S4、H1–H4 区间（互不重叠）按节点随机生成；I1–I5 握手前签名包从模板中选择（如 QUIC、DNS 外观）。镜像已实现 S1–S4 与互不重叠的 H1–H4 区间按节点随机生成，以及 I1–I5 的变量与标签校验；I 包模板尚未提供。
- 端口默认留空，部署时按节点随机选择 UDP 高端口；UDP 443 留给 Hysteria2。
- 对未认证数据包无回应，端口扫描不可见。

## 客户端配置导出

每个客户端（设备）一份配置，包含该节点所有启用的入口和切换策略：

| 客户端                 | 格式                | 入口                                               | 切换策略                   |
| ---------------------- | ------------------- | -------------------------------------------------- | -------------------------- |
| Xray / v2rayN 系       | Xray JSON、分享链接 | 1、2、3                                            | `balancer` + `observatory` |
| Clash Meta (mihomo) 系 | YAML                | 1、2、3、4                                         | `url-test` / `fallback` 组 |
| sing-box 系            | JSON                | 1、3（官方版不支持 XHTTP；AmneziaWG 仅分支版支持） | `urltest` 组               |
| Shadowrocket           | 分享链接 / 订阅     | 1、3，XHTTP 支持待验证                             | 由客户端分组策略决定       |
| AmneziaVPN             | `.conf`             | 4                                                  | —                          |

各客户端对字段的支持以实现时的版本为准，生成器按格式各自测试。

导出方式：

- 默认在控制台登录后下载文件或显示二维码，凭据不出现在 URL、日志或浏览器存储中。
- 订阅链接（可选，默认关闭）：每个客户端一个独立随机令牌，库中只存哈希，可单独吊销；链接本身即凭据，需要在界面上明确提示。

## 监控

代理程序每次轮询附带状态，节点页只显示这些真实数据：

- 节点：在线状态（最后一次通过验证的签名请求在 90 秒内）、代理程序版本、配置版本、应用错误。
- 入口：容器状态、端口监听、REALITY 借用站点可达性。
- 流量：Xray 统计 API、Hysteria2 流量 API、`awg show` 的按客户端收发字节和最近握手时间。

未接入或数据缺失时显示“未知”，不补默认值。

## 数据模型（SQLite）

- `nodes`：名称、公网地址、状态、签名公钥、配置版本、最后上报时间。
- `node_enrollments`：令牌哈希、节点、过期时间、是否已使用。
- `inbounds`：节点、类型、端口、参数 JSON（不含节点私钥）。
- `clients`：名称、备注、启用状态。
- `client_credentials`：客户端 × 入口，加密的凭据。
- `node_reports`：最近一次状态上报，只保留最新一份和有限历史。

## 界面

- 节点列表：真实状态、各入口健康、流量。
- 节点详情：入口开关与参数、注册命令（令牌只显示一次）、为未注册节点重新签发令牌、吊销、删除已吊销节点。
- 客户端：创建、启用/停用、按格式导出、二维码。
- 所有写操作走现有会话认证；敏感操作（创建节点并签发注册令牌、吊销节点、导出配置）需要重新输入密码。

## 测试

- Go：配置渲染用黄金文件测试；签名、重放、吊销、令牌核销的单元测试；可用时在 CI 中用官方镜像执行 `xray run -test` 等校验生成的配置。
- 端到端：控制台与真实 `veilpost-agent` 联调。代理程序需要一种不启动容器的运行方式，只渲染并校验配置；这属于测试专用代码路径，具体形式需要确认（见下）。
- 不 Mock 控制台接口，不在生产代码中加入测试专用端点。

## 分阶段实施

1. 节点注册与控制通道：注册令牌、签名请求、长轮询、在线状态；节点页显示真实状态。
2. VLESS + REALITY + Vision 与 XHTTP 入口：配置下发、校验、健康检查。
3. Hysteria2 与 AmneziaWG 入口。
4. 客户端管理与五种格式导出。
5. 流量统计与监控页面。

每个阶段独立可用，附带测试和文档更新。
